数组是一种线性表的数据结构，用**一组连续的内存空间，来存储一组相同类型的数据**。

## 数组的随机访问

连续的内存空间和相同类型的数据，使得数组可以实现**随机访问**。但是也让数组的其他操作变得效率低下，比如在数组中插入或删除一个值，为了保证数据的连续，就必须进行数据搬移。

例如：一个长度为 10 的 `int` 类型的数组 `a := new([10]int)`。计算机给数组 `a[10]`，分配了一块连续内存空间 `1000～1039`，其中，内存块的首地址为 `base_address = 1000`。

计算机会给每个内存单元分配一个地址，计算机通过地址来访问内存中的数据。当计算机需要随机访问数组中的某个元素时，它会通过下面的寻址公式，计算出该元素存储的内存地址：

```
a[i]_address = base_address + i * data_type_size
```

`data_type_size` 表示数组中每个元素的大小。

## 数组的插入和删除

为什么说数组的插入和删除效率低？

比如一个数组的长度为 n，如果要插入一个元素在 k 位置，时间复杂度是多少?

1. 如果在数组的**末尾插入**，那么不需要移动数据，在末尾加入元素即可，这时是最好时间复杂度，为 `O(1)`。
2. 如果在数组的**开头插入**元素，那么所有元素依次向后移动一位，这时是最坏时间复杂度，为 `O(n)`。由于在每个位置插入的概率是一样的，那么平均时间复杂度为 `(1 + 2 + ...n)/n = O(n)`。
3. 如果删除数组末尾的数据，则最好情况时间复杂度为 `O(1)`；
4. 如果删除开头的数据，则最坏情况时间复杂度为 `O(n)`；

### 如何避免移动数据

1. 如果数组是有序的，那么插入元素就必须移动数据。
2. 对于**无序的数组**，如果要在 k 位置插入元素，为了避免移动数据，可以直接将 k 位置的原数据移动到数据末尾，把新的元素放在 k 位置。

## 为什么数组的下标都是从 0 开始

下标就是"偏移 (offset)"，数组 a 的首地址是 `a[0]`，也就是偏移为 0 的位置。`a[k]` 就表示偏移 k 个 `data_type_size` 的位置，那么 `a[k]` 内存地址为 `a[k]_address = base_address + k * data_type_size`。

但是如果数组从 1 开始，`a[k]` 内存地址就是 `a[k]_address = base_address + (k - 1) * data_type_size`，可以看出**多了一次减法运算， CPU 就多一次减法指令**。对于数组这种基础数据结构，少一次操作就可以提高一点效率。

也可能是历史原因，C 语言是从 0 开始，之后的语言也都效仿了 C 语言。

## 为什么 Javascript 的数组可以存储不同类型的数据

JavaScript 的数组能够存储不同类型的值（如数字、字符串、对象等），是因为它的底层实现基于动态类型系统和灵活的对象模型。

JavaScript 的数组本质上是**特殊类型的对象（Object）**，数组的每个元素实际上是对象的属性。当你访问数组的元素时，实际上是在访问对象的属性。由于对象的属性可以是任意类型的值，因此数组可以存储不同类型的数据。

例如：

```javascript
let arr = [1, "hello", true];
```

在内部，数组可能被表示为：

```javascript
{
  "0": 1,
  "1": "hello",
  "2": true,
  "length": 3
}
```

### 内存分配和优化

尽管 Javascript 的数组可以存储不同类型的值，但 JavaScript 引擎会进行一些优化以提高性能。例如，V8 引擎会尽量让数组保持相同类型的元素，以便使用高效的存储方式。

V8 引擎会根据数组的元素类型，使用不同的存储策略：

| Elements Kind            | 描述                     | 存储方式               | 性能     |
|--------------------------|--------------------------|------------------------|----------|
| PACKED_SMI_ELEMENTS      | 小整数数组（Smi: Small Integer） | 连续存储（高效）       | 🚀 最快  |
| HOLEY_SMI_ELEMENTS       | 稀疏小整数数组           | 哈希表 + 指针（慢）    | ❌ 较慢  |
| PACKED_DOUBLE_ELEMENTS   | 紧凑浮点数数组（double） | 连续存储（高效）       | ✅ 较快  |
| HOLEY_DOUBLE_ELEMENTS    | 稀疏浮点数数组           | 哈希表 + 指针（慢）    | ❌ 较慢  |
| PACKED_ELEMENTS          | 紧凑对象数组（对象指针） | 指针数组 + 对象存储    | ✅ 一般  |
| HOLEY_ELEMENTS           | 稀疏对象数组             | 哈希表 + 指针（慢）    | 🐌 最慢  |

V8 不会预先分配数组的存储类型，而是在运行时动态优化。如果数组的类型发生变化，V8 需要重新分配内存，导致性能下降。

Javascript 中提供了 [ArrayBuffer](https://javascript.ruanyifeng.com/stdlib/arraybuffer.html#toc0) 对象，它可以创建连续的内存。

ArrayBuffer 对象是一个表示固定长度的原始二进制数据缓冲区的类。它不能直接读写，只能通过视图（TypedArray）来读写。
